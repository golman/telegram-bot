# Работа с кодом бота

## Перед началом

1. Прочитай `TODO.md` и найди пункт, над которым работаешь. Не расширяй скоуп: смежные проблемы записывай в `TODO.md`, а не чини попутно.
2. Документацию telego и Telegram Bot API бери через Context7 (`mcp__plugin_context7_context7__*`), а не по памяти. Версия telego указана в `go.mod`, сверяйся с ней.

## Инварианты кода

- **Одна горутина.** Обновления и тикер обрабатываются в `VBBot.Run` (`internal/bot/bot.go`). `mediamsg` — map без мьютекса. Новая горутина допустима только вместе с синхронизацией и тестом с `-race`.
- **Никаких `os.Exit` / `panic` вне `main` (`cmd/telegram-bot`).** Ошибки запуска `run(getenv, stdout) int` (`cmd/telegram-bot/main.go`) логирует и возвращает код выхода, `main` передаёт его в `os.Exit`; тесты запуска — `cmd/telegram-bot/main_test.go`. Ошибка одного пользователя не должна останавливать бота. Ошибки логируются, пользователь получает понятный текст на русском, сырой текст ошибки API ему не показывается.
- **Логи** — только `log/slog` с полями по правилам раздела «Логи» в `CLAUDE.md`, без `fmt`-подстановок в сообщение. Формат и вывод настраивает `internal/logging` (`NewHandler`, `Bootstrap`, `Setup`, `BotOptions` для telego); свой обработчик не заводи. Пакет `log` не используй.
- **Время** бери через `vbbot.clock()`, а не `time.Now()`: в тестах его подменяет `useFakeClock`.
- **Конфиг** читается только через `config.Load` (`internal/config`) — чистую функцию без логов: некорректные значения заменяются умолчаниями и возвращаются списком `config.Warning`, а `run` (`cmd/telegram-bot/main.go`) пишет их после настройки файла логов. Прямой `os.Getenv` вне `main` не используй (`run` получает `getenv` параметром). Новая переменная окружения — поле в `config.Config`, разбор в `Load`, случай в `TestLoad` и описание в `CLAUDE.md` (и в README, когда он появится).
- **Тексты для пользователей** — константы в `internal/bot/phrases.go`, на русском; вид поста (`post.DeprecatedPrefix`, `post.AuthorSuffix`) — в `internal/post`.
- **nil-проверки** для всего, что Telegram может не прислать: `Message.From`, `ReplyToMessage`, недоступное `CallbackQuery.Message` (`IsAccessible()`). После ответа об ошибке обязательно `return`.
- **Callback-запрос** всегда завершается `AnswerCallbackQuery`, в том числе при ошибке, иначе на кнопке остаются «часики».
- **Приватный чат** определяется по `Chat.Type == "private"`.

## Entities и форматирование

- `Offset` и `Length` в `MessageEntity` считаются в **UTF-16 code units**, а не в байтах и не в рунах. Кириллица занимает 1 unit, эмодзи вне BMP — 2. Для подсчёта используй `telegoutil.UTF16TextLen`, для сборки текста с entities — `telegoutil.MessageEntities`.
- Если перед пользовательским текстом добавляется префикс, entities пользователя нужно **сдвинуть на UTF-16-длину префикса**. Простой `append` без сдвига ломает форматирование.
- Пост должен собираться **одной функцией** для публикации, пометки «Не актуально» и восстановления. Иначе посты начинают расходиться по виду (так раньше Bold был при отправке и пропадал после restore).
- Тело поста не получает своего форматирования от бота: в пост попадает только разметка автора, при «Не актуально» добавляется лишь зачёркивание.
- Подпись (caption) медиа ограничена 1024 символами, текст сообщения — 4096, вместе с припиской «by: …» и префиксом «Не актуально». Проверяй через `post.TextLimit` (`internal/post`) / `rejectTooLong`, а не отдельной формулой.

## Callback data

- Формат: `<действие>_<chatID>_<messageID>`, лимит Telegram — **64 байта**.
- chatID из callback data сверяй с `channelId`, клиентским данным не доверяй.
- Новые действия добавляй константами и через общую пару encode/decode, а не через ручной `strings.Split`.

## Медиагруппы

- Элементы альбома приходят отдельными update с общим `MediaGroupID`. Подпись и её entities могут быть на **любом** элементе, а не только на первом: бери их из того элемента, где есть caption.
- Авторизацию, фильтры и служебные ответы выполняй один раз на альбом, а не на каждый элемент.
- В альбоме бывают видео и документы, а не только фото. Неподдерживаемый тип нужно явно отклонять одним сообщением.

## Тесты

- Табличные тесты (`[]struct{ name string; ... }` + `t.Run`), только стандартный `testing`, без внешних фреймворков, пока они не нужны.
- В первую очередь покрываются чистые функции: сборка поста и сдвиг entities (с эмодзи и кириллицей), encode/decode callback data, разбор конфига (`config.Load`), переходы состояний медиагрупп.
- Вызовы Telegram API тестируются через фейковый Bot API (`newTestBot` в `internal/bot/fakeapi_test.go`), без сети. Общие тестовые данные и хелперы — в `internal/bot/testhelpers_test.go`. Логи в тестах перехватывай `testutil.CaptureLog(t)` (`internal/testutil`), а не своим обработчиком; тесты `internal/logging` из-за этого внешние (`package logging_test`).
- Баг сначала воспроизводится падающим тестом, потом чинится.
- Силу новых тестов проверяй мутациями: сломай исправленное место в копии модуля (в scratchpad) и убедись, что тест падает. Выжившую мутацию закрывай тестом или объясняй, почему она эквивалентна.

## Проверка перед коммитом

Выполни всё и приложи результат. Если что-то упало, сообщи об этом, а не скрывай:

```sh
gofmt -l .                 # вывод должен быть пустым
go vet ./...
go test -race ./...
go build ./...
# если установлены:
staticcheck ./...
govulncheck ./...
```

## Завершение

- Коммит и PR — на русском, по правилам `CLAUDE.md`. Коммитит, мержит и пушит только пользователь: `git commit`, merge и push не выполняй никогда, даже на «можно коммитить». Готовую правку добавь в стейдж и дай команду коммита.
- В скилле `finishing-a-development-branch` всегда выбирается вариант 3 («оставить ветку как есть»). PR создаётся только по явной просьбе пользователя в текущем диалоге.
- Ссылки установленных скиллов на `superpowers:test-driven-development` означают скилл `tdd`, а на `code-review` — встроенный `/code-review`.
- В `TODO.md` пункт отмечается `[x]` (без хеша) в том же стейдже, что и изменение, чтобы закрыться одним коммитом.
- Если поведение бота изменилось, обнови разделы «Архитектура» и «Подводные камни» в `CLAUDE.md`.
