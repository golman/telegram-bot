# Работа с кодом бота

## Перед началом

1. Прочитай `TODO.md` и найди пункт, над которым работаешь. Не расширяй скоуп: смежные проблемы записывай в `TODO.md`, а не чини попутно.
2. Документацию telego и Telegram Bot API бери через Context7 (`mcp__plugin_context7_context7__*`), а не по памяти. Версия telego указана в `go.mod`, сверяйся с ней.

## Инварианты кода

- **Одна горутина.** Обновления и тикер обрабатываются в `VBBot.Start`. `mediamsg` — map без мьютекса. Новая горутина допустима только вместе с синхронизацией и тестом с `-race`.
- **Никаких `log.Fatal*` / `panic` вне `main`.** Ошибка одного пользователя не должна останавливать бота. Ошибки логируются, пользователь получает понятный текст на русском, сырой текст ошибки API ему не показывается.
- **Конфиг** читается только через `getEnvOrDefault`, `getEnvIntOrDefault`, `getEnvInt64OrDefault`, `getEnvBoolOrDefault`. Новая переменная окружения документируется в `CLAUDE.md` (и в README, когда он появится).
- **Тексты для пользователей** — константы в `phrases.go`, на русском.
- **nil-проверки** для всего, что Telegram может не прислать: `Message.From`, `ReplyToMessage`, недоступное `CallbackQuery.Message` (`IsAccessible()`). После ответа об ошибке обязательно `return`.
- **Callback-запрос** всегда завершается `AnswerCallbackQuery`, в том числе при ошибке, иначе на кнопке остаются «часики».
- **Приватный чат** определяется по `Chat.Type == "private"`.

## Entities и форматирование

- `Offset` и `Length` в `MessageEntity` считаются в **UTF-16 code units**, а не в байтах и не в рунах. Кириллица занимает 1 unit, эмодзи вне BMP — 2. Для подсчёта используй `utf16.Encode([]rune(s))` или `telegoutil.MessageEntities`.
- Если перед пользовательским текстом добавляется префикс, entities пользователя нужно **сдвинуть на UTF-16-длину префикса**. Простой `append` без сдвига ломает форматирование.
- Пост должен собираться **одной функцией** для публикации, пометки «Не актуально» и восстановления. Иначе посты начинают расходиться по виду (так раньше Bold был при отправке и пропадал после restore).
- Тело поста не получает своего форматирования от бота: в пост попадает только разметка автора, при «Не актуально» добавляется лишь зачёркивание.
- Подпись (caption) медиа ограничена 1024 символами, текст сообщения — 4096. Учитывай длину приписки «by: …».

## Callback data

- Формат: `<действие>_<chatID>_<messageID>`, лимит Telegram — **64 байта**.
- chatID из callback data сверяй с `channelId`, клиентским данным не доверяй.
- Новые действия добавляй константами и через общую пару encode/decode, а не через ручной `strings.Split`.

## Медиагруппы

- Элементы альбома приходят отдельными update с общим `MediaGroupID`. Подпись и её entities могут быть на **любом** элементе, а не только на первом: бери их из того элемента, где есть caption.
- Авторизацию, фильтры и служебные ответы выполняй один раз на альбом, а не на каждый элемент.
- В альбоме бывают видео и документы, а не только фото. Неподдерживаемый тип нужно явно отклонять одним сообщением.

## Тесты

- Табличные тесты (`[]struct{ name string; ... }` + `t.Run`), только стандартный `testing`, без внешних фреймворков, пока они не нужны.
- В первую очередь покрываются чистые функции: сборка поста и сдвиг entities (с эмодзи и кириллицей), encode/decode callback data, env-хелперы, переходы состояний медиагрупп.
- Вызовы Telegram API тестируются через интерфейс над нужными методами `*telego.Bot`, без сетевых запросов.
- Баг сначала воспроизводится падающим тестом, потом чинится.

## Проверка перед коммитом

Выполни всё и приложи результат. Если что-то упало, сообщи об этом, а не скрывай:

```sh
gofmt -l .                 # вывод должен быть пустым
go vet ./...
go test -race ./...
go build ./...
# если установлены:
staticcheck ./...
govulncheck ./...
```

## Завершение

- Коммит и PR — на русском, по правилам `CLAUDE.md`. Коммитит и мержит пользователь, если не попросил иначе.
- В скилле `finishing-a-development-branch` по умолчанию выбирается вариант 3 («оставить ветку как есть»). Локальный merge, push и создание PR выполняются только по явной просьбе пользователя в текущем диалоге.
- Ссылки установленных скиллов на `superpowers:test-driven-development` означают скилл `tdd`, а на `code-review` — встроенный `/code-review`.
- В `TODO.md` пункт **не отмечается** до мержа в `master`. После мержа ставится `[x]` с хешем или номером PR.
- Если поведение бота изменилось, обнови разделы «Архитектура» и «Подводные камни» в `CLAUDE.md`.
