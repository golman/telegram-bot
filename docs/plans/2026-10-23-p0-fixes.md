# План: критичные исправления и общая сборка поста

> Выполнять по задачам по порядку, шаги отмечать `- [x]` по ходу работы. При выполнении применяются скиллы `go-telego`, `tdd`, `systematic-debugging`, `verification-before-completion`.

**Цель:** бот перестаёт падать на кнопках, ошибках API и закрытом канале обновлений, а посты собираются одной функцией и не теряют форматирование при «Не актуально» / «Восстановить».

**Архитектура:** сборка текста поста выносится в чистую функцию `buildPost` (`post.go`), которую используют и публикация, и callback-обработчик. Два почти одинаковых обработчика delete/restore заменяются одним (`callback.go`) с разбором callback data, проверками на nil и ровно одним `AnswerCallbackQuery`. Накопление альбома переносится в методы `MediaMessage`, а цикл событий получает выход при закрытом канале и `recover`.

**Стек:** Go 1.26, `github.com/mymmrac/telego` v1.9.0 и `telegoutil`, стандартный `testing`.

**Спецификация:** раздел «Критично» и пункт «Общая сборка поста» в [`TODO.md`](../../TODO.md).

## Общие ограничения

- Формат callback data не меняется: `<действие>_<chatID>_<messageID>`, действия `delete` и `restore`. Кнопки, отправленные до деплоя, должны продолжать работать.
- Внешний вид опубликованных постов не меняется, кроме одного решения, принятого после ревью: бот больше не делает тело текстового поста Bold, в пост попадает только разметка автора (как у подписей к фото); приписка ровно `"\n\n by: "` и упоминание автора через `TextMentionWithID`; префикс неактуального — ровно `"Не актуально.\n\n"`, тело, приписка и упоминание зачёркнуты.
- Вся обработка остаётся в одной горутине `Start`, новых горутин нет (кроме тестов).
- Новых зависимостей нет. UTF-16-длина считается через `telegoutil.UTF16TextLen`.
- Тексты для пользователей — константы в `phrases.go`, на русском.
- Пункты из других разделов `TODO.md` не трогаются, даже если код рядом.
- Коммитит пользователь: задача заканчивается предложением коммита, а не самим коммитом.

## На что смотреть при ревью

1. Кнопка из подтверждения, отправленного до деплоя (`delete_-1001234567890_42`), должна разбираться как раньше. Тест в задаче 2.
2. Тело с эмодзи вне BMP и кириллицей: entities пользователя после префикса стоят на тех же символах. Тест в задаче 1.
3. Автор удалил исходное сообщение (`ReplyToMessage == nil`): ответ на кнопку «Исходное сообщение не найдено», без паники. Тест в задаче 1.
4. Старое подтверждение альбома ссылается на первое фото без подписи: ответ с ошибкой, `EditMessageText` по фото-посту не вызывается. Тест в задаче 1.
5. У пользователя нет фамилии: имя автора без висящего пробела. Тест в задаче 1.
