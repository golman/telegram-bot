# Разделение на пакеты: план

> **Для исполнителей-агентов:** обязательный скилл — `superpowers:subagent-driven-development` (рекомендуется) или `superpowers:executing-plans`. Шаги отмечаются чекбоксами (`- [ ]`).

**Цель:** разложить плоский `package main` (~1100 строк, 11 файлов) по пакетам с понятными границами, заодно закрыв пункты «Имена в стиле Go» и «Имя модуля»; поведение бота не меняется.

**Архитектура:** сначала выносятся листовые пакеты без зависимостей от бота (`post`, `tgapi`, `config`, `logging`), затем всё остальное переезжает в `internal/bot`, а `main` — в `cmd/telegram-bot`. Переименования в стиле Go идут отдельной задачей после переноса, чтобы git видел перенос файлов, а ревьюер — чистый diff переименований.

**Стек:** Go 1.26.7+, `github.com/mymmrac/telego` v1.12.1, `log/slog`, lumberjack.

**Спецификация:** пункты `TODO.md` «Разделить на пакеты», «Имена в стиле Go», «Имя модуля»; правила — `CLAUDE.md` и `.claude/skills/go-telego/SKILL.md`.

## Глобальные ограничения

- Поведение бота не меняется: тексты, формат логов, коды выхода, тайминги альбомов — как в `master` на момент начала.
- Формат callback data `<действие>_<chatID>_<messageID>` не меняется — в чатах лежат старые кнопки.
- Модуль: `github.com/golman/telegram-bot` (совпадает с `origin`).
- Псевдоним импорта telego — `telego` (не `tgbotapi`); `telegoapi` — `ta`, `telegoutil` — `tu`.
- Всё на русском: комментарии, логи, сообщения тестов («получено X, ожидалось Y»).
- Пакет `log` не используется, только `log/slog`; время в боте — через `clock()`.
- Коммитит пользователь. Каждая задача заканчивается стейджем поимённых файлов (не `git add .`) и командой коммита для пользователя; префикс `рефакторинг:`.
- После каждой задачи: `gofmt -l .` пусто, `go vet ./...`, `go test -race -count=3 -shuffle=on ./...`, `go run honnef.co/go/tools/cmd/staticcheck@v0.8.2 ./...`, `go build ./...`.
- **Ни один тест не теряется.** Перед задачей и после неё считается `go test -v -count=1 ./... 2>&1 | grep -c -- '--- PASS'`; после задачи число не меньше (больше — только за счёт новых тестов этой задачи, их число указывается).

## Целевая структура

```
cmd/telegram-bot/main.go      запуск: config → logging → telego → bot.Run, коды выхода
internal/config/              Config, Load (чистая, без логов), Warning
internal/logging/             NewHandler, Bootstrap, Setup, адаптер логов telego, BotOptions
internal/tgapi/               rateLimitCaller, timeoutCaller, NewCaller, LongPollTimeoutSeconds
internal/post/                Source, Build, TextLimit, FromMessage, DisplayName, DeprecatedPrefix, AuthorSuffix
internal/bot/                 Bot, цикл событий, обработка сообщений, альбомы, кнопки, отправка, тексты
internal/testutil/            CaptureLog (общий для тестов всех пакетов)
```

`internal/bot` зависит от `config`, `post`; `cmd` — от всех; остальные пакеты друг от друга не зависят, кроме `logging → config` и `testutil → logging`.

## На что смотреть при ревью

- **Docker-образ собирается из нового пути.** `Dockerfile` копирует `*.go` из корня и собирает `.` — после переноса это пустая сборка. Проверка: `docker build` и запуск контейнера с фейковым токеном (задача 6).
- **Предупреждение о некорректном `LOG_LEVEL` попадает в файл,** а не только в stdout. Сейчас это обеспечивает порядок внутри `setupLogging`; после разделения порядок задаёт `main`. Проверка: тест `TestRunLogsConfigWarningsToFile` (задача 6).
- **Коды выхода не меняются:** без `BOT_TOKEN` — 1 и запись «не задан BOT_TOKEN», по SIGTERM — 0 и «бот остановлен». Проверка: запуск собранного бинарника (задача 6).
- **Тесты не теряются при переносе.** Перенос тестов между пакетами — главный риск тихо потерять проверку. Проверка: счётчик `--- PASS` в каждой задаче.
- **Старые кнопки работают.** Переименования в задаче 7 не должны задеть строковые значения `delete`/`restore` и разбор callback data. Проверка: `TestDecodeCallback` с данными «кнопка до деплоя» остаётся без изменений.
