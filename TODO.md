## Правила ведения

- Разделы идут от критичного к косметике, а внутри раздела пункты стоят по убыванию важности.
- Новый пункт добавляется в подходящий раздел, между открытыми пунктами, исходя из его важности относительно них. Номеров нет: ссылаться на пункт можно по его заголовку (выделен жирным).
- Пункт отмечается `[x]` в том же коммите, что и само изменение, без хеша: коммит находится через `git log -S "[x] **Заголовок пункта.**" -- TODO.md`. У пунктов, закрытых раньше отдельным коммитом, хеш указан рядом с отметкой.
- Если для группы пунктов написан подробный план, ссылка на него стоит в начале раздела.

## Критично: бот падает или портит посты

План: [docs/plans/2026-10-23-p0-fixes.md](docs/plans/2026-10-23-p0-fixes.md) (покрывает весь раздел и пункт «Общая сборка поста»).

- [x] **Зацикливание на закрытом канале обновлений.** В `Start` нет проверки `update, ok := <-ch`. telego закрывает канал при остановке long polling, после чего цикл крутится на пустых `Update` и загружает CPU на 100%. (`b495216`)
- [x] **Паника на nil в callback-обработчиках.** После «Message is not accessible» нет `return`. `ReplyToMessage == nil`, если автор удалил исходное сообщение, и кнопка роняет процесс. (`b495216`)
- [x] **`log.Fatalln` в `authByChannel`.** Любая ошибка `GetChatMember` (таймаут, 429) завершает процесс. Нужно логировать ошибку, отвечать «попробуйте позже» и возвращать `false`. (`b495216`)
- [x] **Нет `recover` при обработке update.** Одна паника останавливает бота для всех. (`b495216`)
- [x] **Съезжает форматирование при «Не актуально».** Перед текстом вставляется префикс, а entities пользователя не сдвигаются на его UTF-16-длину. (`b495216`)
- [x] **Подпись альбома не на первом фото.** Entities берутся из первого элемента, а caption — из любого. Подтверждение отвечает на первое фото, поэтому delete/restore не видят подписи и вызывают `EditMessageText` на фото-посте. (`b495216`)
- [x] **Пост меняет вид после «Восстановить».** При публикации текст делался Bold, а delete/restore пересобирали пост без Bold. Решено: бот вообще не добавляет Bold, в пост попадает только разметка автора. (`b495216`)
- [x] **«Часики» на кнопке при ошибке.** В ветках с ошибками не вызывается `AnswerCallbackQuery`. (`b495216`)

## Важно: надёжность, безопасность, эксплуатация

- [x] **`.gitignore` не защищает секреты и данные.** Нет `logs/`, `.env`, собранного бинарника. Логи с данными пользователей или токен можно случайно закоммитить. (`d88af50`)
- [x] **Graceful shutdown.** `signal.NotifyContext` для SIGINT/SIGTERM, отправка накопленных медиагрупп при остановке, `ticker.Stop()`. Сейчас `Start` при закрытии канала обновлений просто выходит, и процесс завершается с кодом 0: supervisor, перезапускающий только при ошибке, бота не поднимет. Неожиданное закрытие канала должно давать ненулевой код выхода. (`1a16df3`)
- [x] **Паника при отправке альбома роняет процесс.** `recover` в `dispatch` покрывает только обработку update, а ветку тикера (`sendMediaGroup`) нет. При обёртке переводить группу в `ToDelete` до отправки, иначе после `recover` отправка будет повторяться и паниковать на каждом тике. Конкретный источник паники: `sentMsg[0]` в `sendMediaGroup` и `sendPhotoMessage` без проверки длины ответа. (`61c52a8`)
- [x] **Опоздавшие элементы альбома теряются.** Фото, пришедшее после отправки группы, добавляется в уже отправленную `MediaMessage` и пропадает. Если группа уже удалена, создаётся новая без подписи, и пользователь получает «Сообщение не может быть пустым». Решено окном ожидания около минуты после отправки: опоздавшие фото не публикуются, автор получает одно уведомление. (`01142b6`)
- [x] **Длина поста не проверяется.** Подпись ограничена 1024 символами, текст — 4096, вместе с припиской «by: …». При превышении пользователь видит сырую ошибку API. (`8851733`)
- [x] **Сырые ошибки API уходят пользователю.** `handleError` пересылает текст ошибки. Пользователю нужен понятный текст, подробности — только в лог. При 429 повторять запрос по `retry_after`. (`55b8909`)
- [x] **Таймауты.** Корневой ctx и `context.WithTimeout` на вызовы API вместо `context.Background()`. Сделано дедлайном на каждую попытку в `timeoutCaller`; контекст остановки в запросы не передаётся, чтобы после сигнала дообработать буфер и альбомы. (`8b612e0`)
- [x] **Неподдерживаемые типы сообщений.** Стикер, голосовое, видео, геолокация попадают в `sendPlainMessage` и получают ответ «Сообщение не может быть пустым». Нужен явный отказ с понятным текстом. (`1252e43`)
- [ ] **Подделка messageID в callback data.** chatID теперь сверяется с каналом, но messageID — нет: если Telegram не сверяет callback data с кнопкой, модифицированный клиент может указать чужой пост канала, и бот заменит его текст текстом своего исходного сообщения. Закрывается хранилищем объявлений (сверять автора поста) или подписью callback data (HMAC).
- [x] **Проверка chatID из callback data.** Сверять с `channelId`, клиентским данным не доверять. Сделано в задаче 2 плана критичных исправлений. (`b495216`)
- [x] **Проверка приватного чата.** `Chat.Type == "private"` вместо `Chat.ID < 0`, проверка `Message.From != nil`.
- [x] **Повторное нажатие кнопки показывает ошибку.** Telegram отвечает «message is not modified», и пользователь видит «Не удалось изменить объявление в канале», хотя пост уже в нужном состоянии. Распознавать эту ошибку как успех.
- [x] **Логи telego мимо файла.** `WithDefaultDebugLogger()` пишет в stderr и печатает тела запросов. Нужен свой логгер через `WithLogger` с маскированием токена (сейчас его заменяет на `BOT_TOKEN` `defaultReplacer` telego) и уровень через `LOG_LEVEL`.
- [ ] **Restore подтягивает отредактированный текст.** Пост пересобирается из текущей версии исходного сообщения, поэтому восстановление незаметно меняет содержимое поста и обходит фильтры. Полностью решается хранилищем объявлений.
- [x] **Недоступный файл логов молча игнорируется.** `logging.Setup` создаёт только каталог, а файл lumberjack открывает при первой записи; если файл недоступен для записи, `io.MultiWriter` возвращает ошибку, а slog её отбрасывает — бот работает с кодом 0, логи идут только в stdout, предупреждения нет. Открывать файл в `Setup` (ошибка → код 1) и тест на каталог без права записи.

## Качество кода

- [x] **Общая сборка поста.** Одна функция `buildPost` для публикации, «Не актуально» и восстановления; общий обработчик delete/restore; хелпер `displayName` без висящего пробела. Входит в план критичного раздела. (`b495216`)
- [x] **`send.go` собирает `postSource` вручную.** `sendPlainMessage` и `sendPhotoMessage` повторяют логику `postSourceFromMessage`: публикация и кнопки выбирают текст или подпись по-разному и разойдутся при добавлении видео. Использовать `postSourceFromMessage` и в `send.go`.
- [x] **Тесты на остальное.** Env-хелперы. Обработчики уже тестируются через фейковый Bot API (`fakeapi_test.go`). Свести повторяющиеся тестовые константы и хелперы (`testAlbumConfirmMessage` / `testConfirmMessageID`, `testAlbumAuthorID` / `authUserID`, `confirmMsg` / `pressButton`, `containsEntity`) в общий файл, единый стиль сообщений («ожидалось»).
- [x] **Один ответ на альбом.** Авторизация, фильтры и служебные ответы выполняются на каждый элемент: без подписки пользователь получает «Вы не подписаны» столько раз, сколько фото. Пустую подпись альбома проверять до обещания «будет отправлено». Ещё один сценарий: если `GetChatMember` временно упал только на одном элементе, альбом публикуется без этого фото (а если подпись была на нём — без подписи), а автор получает «Не удалось проверить подписку».
- [x] **Медиагруппы по таймауту тишины.** Отправлять через N секунд после последнего элемента, а не по шагам тикера, и исправить текст «через 10 секунд».
- [x] **Перейти на `log/slog`.** Структурированные поля (`user_id`, `media_group_id`, `channel_msg_id`); убрать `log.Println(cm)` из `auth.go`; перевести оставшиеся английские сообщения логов на русский (`logging.go`, `main`, `send.go`).
- [x] **Все тексты в `phrases.go`.** Остатки захардкоженных строк в обработчиках.
- [x] **Разделить на пакеты.** `internal/bot`, `internal/config`, `internal/post`; конфиг одной структурой. Пункты «Имена в стиле Go» и «Имя модуля» из «Косметики» трогают те же строки — их выгоднее сделать вместе с переносом.
