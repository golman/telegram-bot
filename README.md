# telegram-bot

Telegram-бот для доски объявлений в канале. Автор присылает объявление боту в личный чат, бот публикует его в канал с припиской «by: Имя Фамилия» (имя из профиля автора, со ссылкой на профиль) и присылает автору подтверждение с кнопкой «Не актуально». Кнопка зачёркивает пост и ставит над ним «Не актуально.», повторное нажатие («Восстановить») возвращает прежний вид.

Пост при нажатии кнопки собирается заново из исходного сообщения автора. Поэтому кнопка работает, пока автор это сообщение не удалил, а если автор его отредактировал, после нажатия в канале окажется новый текст.

## Что умеет бот

- **Принимает текст, фото с подписью и альбомы из фото с подписью.** Разметку автора (жирный, ссылки и т. п.) сохраняет. Альбом публикует одним постом через 3–4 секунды после последнего фото. Фото, которые дошли до бота уже после публикации альбома, в пост не попадают, и автор получает об этом сообщение.
- **Отклоняет с объяснением** стикеры, голосовые, видео, документы, геолокацию, фото и альбомы без подписи и слишком длинные объявления. Видео и файлы внутри альбома не публикуются, автор получает об этом сообщение; альбом без единого фото отклоняется.
- **Следит за длиной.** Пост целиком — текст, приписка «by: …» и место под пометку «Не актуально» — должен уложиться в лимит Telegram: 4096 символов для текста и 1024 для подписи к фото, эмодзи считаются за два символа и больше. Если не укладывается, бот подскажет, на сколько сократить; у альбома — сразу, как только пришла подпись.
- **Принимает объявления только от подписчиков канала**, включая его администраторов (можно отключить, см. `BOT_AUTH_ENABLED`).
- **Работает только в личном чате**, в группах молчит. На `/start` и `/help` отвечает справкой, как подать объявление (при `BOT_AUTH_ENABLED=true` — и что принимаются объявления только от подписчиков). Другие сообщения, которые начинаются с `/`, молча игнорирует.
- **Переживает сбои Telegram.** Если Telegram ограничил частоту запросов (429), повторяет запрос после указанной паузы. Другие ошибки автору показывает понятным текстом, подробности пишет в лог. Если ответа на публикацию не дождался (сбой сети, таймаут), просит автора сначала проверить канал, а не отправлять объявление снова: пост мог выйти.

## Что нужно

- Docker с Compose v2 (команда `docker compose`) или Go 1.26.7 и новее для запуска без Docker.
- Исходящий доступ по HTTPS к `api.telegram.org`. Входящие порты открывать не нужно: бот сам забирает сообщения у Telegram (long polling).

## Настройка

1. **Создайте бота** у [@BotFather](https://t.me/BotFather) командой `/newbot` и сохраните токен — это `BOT_TOKEN`. Токен уже созданного бота показывает `/mybots` → бот → «API Token». Больше в BotFather ничего настраивать не нужно.
2. **Добавьте бота администратором канала** с правом «Публикация сообщений», других прав не нужно: бот редактирует только свои посты. Без прав администратора он не сможет ни публиковать, ни проверять подписку авторов, поэтому без них бот не запустится.
3. **Узнайте ID канала** — это `CHANNEL_ID`, число вида `-1001234567890`. Например, откройте канал в [Telegram Web](https://web.telegram.org/a/): ID стоит в адресе после `#`. Если ID окажется неверным, бот не запустится и напишет об этом в лог.
4. **Создайте `.env`** из примера и впишите туда токен и ID:

   ```sh
   cp .env.example .env
   ```

   `.env` содержит токен и в git не попадает.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота, обязательно |
| `CHANNEL_ID` | — | ID канала для публикации, обязательно |
| `BOT_AUTH_ENABLED` | `true` | Принимать объявления только от подписчиков канала |
| `LOG_LEVEL` | `info` | `info` или `debug`, регистр не важен. На `debug` в лог попадают тексты объявлений и данные пользователей — только для отладки |
| `LOG_FILE_PATH` | `logs/telegram-bot.log` | Файл логов; в Docker задан в образе: `/app/logs/telegram-bot.log` |
| `LOG_MAX_SIZE_MB` | `20` | Размер файла в МБ, после которого начинается новый |
| `LOG_MAX_BACKUPS` | `5` | Сколько старых файлов хранить |
| `LOG_MAX_AGE_DAYS` | `14` | Сколько дней хранить старые файлы |
| `LOG_COMPRESS` | `true` | Сжимать старые файлы |

Числа `LOG_MAX_*` должны быть больше нуля, логические значения — `true`/`false` (или `1`/`0`). Некорректные `LOG_*` и `BOT_AUTH_ENABLED` заменяются значением по умолчанию, предупреждение пишется в лог. Пустое значение тоже означает значение по умолчанию.

## Запуск

**В Docker** (переменные берутся из `.env`):

```sh
docker compose up -d --build
docker compose logs -f        # логи
docker compose down           # остановка
```

После первого запуска загляните в `docker compose logs`: контейнер перезапускается после любого завершения, поэтому при ошибке настройки (например, «не задан BOT_TOKEN») он будет перезапускаться снова и снова, хотя `up -d` выглядит успешным. Перезапускается он и после перезагрузки хоста, если служба Docker стартует автоматически. При остановке бот дожидается конца текущего запроса к Telegram (до 8 секунд) и публикует альбомы, которые успел получить.

Логи бот пишет и в stdout, и в файл. Вывод для `docker compose logs` Docker хранит отдельно и ротирует: не больше трёх файлов по 10 МБ. Файл логов лежит в томе `<каталог проекта>_logs`, например `telegram-bot_logs`; `docker compose down -v` удаляет и его.

Обновление до новой версии из репозитория:

```sh
git pull
docker compose up -d --build
```

**Локально** (нужен Go 1.26.7 или новее), из корня репозитория:

```sh
bash -c 'set -a; . ./.env; exec go run ./cmd/telegram-bot'
```

Логи пишутся в stdout и в `logs/telegram-bot.log` относительно текущего каталога. Остановка — Ctrl+C. Код выхода после неё будет 1: это код самого `go run`, бот при этом завершился штатно (в логе — «бот остановлен»).

## Проверка

1. Убедитесь, что в логе есть «бот подключён к Telegram» и нет записей `level=ERROR`.
2. Подпишитесь на канал и отправьте боту `/start` — он ответит справкой.
3. Отправьте боту текст объявления: в канале появится пост, а вам придёт подтверждение с кнопкой «Не актуально». Нажмите её — пост зачеркнётся, нажмите «Восстановить» — вернётся прежний вид.

## Если что-то не так

**Как читать лог.** Каждая запись — одна строка вида `time=… level=ERROR msg="что случилось" поле=значение …`. Время в UTC. Суть — в `msg`, подробности ошибки — в поле `err`. Найти ошибки в Docker:

```sh
docker compose logs | grep level=ERROR
```

### Бот не запускается

Бот завершается с кодом 1, причина — в последней строке лога.

| Запись в логе | Причина | Что сделать |
|---|---|---|
| «не задан BOT_TOKEN» | В `.env` нет токена | Впишите `BOT_TOKEN` |
| «не задан или некорректен CHANNEL_ID» | ID не задан, не число или 0. Если не число, выше будет предупреждение с этим значением | Впишите `CHANNEL_ID` вида `-1001234567890` |
| «не удалось создать клиент Bot API» | Токен не похож на токен | Скопируйте токен из BotFather целиком, вида `123456:ABC…` |
| «Telegram не принял токен бота» | Токен неверный или отозван. Если в `err` нет кода `401`, а есть сетевая ошибка, у сервера нет доступа к `api.telegram.org` | Проверьте токен в BotFather или доступ в интернет |
| «бот не может публиковать в канал» | `CHANNEL_ID` не тот (например, без `-100` в начале), бот не администратор канала или у него нет права «Публикация сообщений» | Проверьте ID и права бота, причина — в `err` |
| «у бота настроен webhook» | Telegram отдаёт сообщения бота на другой адрес, а не боту | Снимите webhook, см. ниже |
| «не удалось проверить webhook» | Обычно сетевая ошибка при запуске | Проверьте доступ к `api.telegram.org` |
| «не удалось настроить логирование» | Не удалось создать каталог для логов или открыть файл на запись | Проверьте `LOG_FILE_PATH` и права на каталог |

Если Telegram был недоступен только в момент запуска, в Docker ничего делать не нужно: контейнер перезапустится, и бот поднимется сам, как только связь появится.

**Как снять webhook.** Пока у бота есть webhook, Telegram не отдаёт сообщения через long polling, которым пользуется бот. Сам бот webhook не снимает: он может быть нужен другому сервису. Из корня репозитория посмотрите, куда он ведёт и сколько сообщений ждут доставки, и снимите его:

```sh
bash -c 'set -a; . ./.env; curl -s "https://api.telegram.org/bot$BOT_TOKEN/getWebhookInfo"'
bash -c 'set -a; . ./.env; curl -s "https://api.telegram.org/bot$BOT_TOKEN/deleteWebhook"'
```

Сообщения из `pending_update_count` — объявления, которые авторы уже прислали: после снятия webhook бот их опубликует. Если они не нужны, добавьте к адресу `deleteWebhook` параметр `?drop_pending_updates=true`. Токен берётся из `.env` и в историю shell не попадает. Затем запустите бота снова (Docker перезапустит контейнер сам).

### Бот работает, но что-то не так

- **В логе каждые 8 секунд ошибка `getUpdates` с кодом 409 (`Conflict`).** С этим токеном запущена ещё одна копия бота, например локально и в Docker. Бот при этом не завершается и повторяет запрос; остановите лишнюю копию.
- **Авторы получают «Не удалось проверить подписку на канал»** (или, при `BOT_AUTH_ENABLED=false`, «Не удалось опубликовать объявление в канале»). Права бота проверяются только при запуске: возможно, их сняли позже, или Telegram временно не отвечает. Подробности — в записях «не удалось проверить подписку» и «не удалось опубликовать объявление».
- **Автор получил «Не удалось дождаться ответа Telegram, объявление могло опубликоваться».** Связь с Telegram оборвалась во время публикации. Пост мог выйти, поэтому автору предложено сначала проверить канал. Подробности — в записи «не удалось опубликовать объявление».
- **Кнопка под подтверждением отвечает ошибкой:**
  - «Исходное сообщение не найдено, изменить объявление нельзя» — автор удалил своё сообщение с объявлением. Пост в канале можно изменить или удалить только вручную.
  - «Не удалось изменить объявление в канале» — пост удалили из канала, у бота сняли права или отредактированный автором текст стал длиннее лимита. Подробности — в записи «не удалось изменить пост в канале».
  - «Кнопка устарела или повреждена» — кнопка ведёт не в текущий канал, например после смены `CHANNEL_ID`.

```sh
go test -race ./...

```
